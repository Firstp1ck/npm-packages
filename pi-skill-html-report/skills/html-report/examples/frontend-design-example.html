The report skill decides what the document must prove. The frontend skill decides how this subject should look and sound. Neither gets to erase the other's constraints.

Color

Canonical palette, new hierarchy

The navy, raised panels, blue interaction color, and semantic statuses remain intact. Yellow carries the editorial proof marks because it already means attention in the report system.

Type

A book face makes the argument

A restrained local serif gives the hero an editorial voice. System sans handles explanation, and monospace labels decisions and source roles. No font leaves the machine.

Layout

The margin becomes evidence

The wide proof rail turns critique notes into structure. On a narrow screen it becomes a horizontal annotation strip, so the concept survives without squeezing the text.

Restraint

One risk is enough

The proof rail carries the surprise. Cards, tables, and diagrams stay quiet. The page drops metric tiles because this subject has no honest measurements to show.

A working process, not a style swap

  1. Choose the subject and the page's one job

    Name the audience, decision, evidence, and uncertainty. If the subject is vague, the design will default to a familiar template.

  2. Lock the report contract

    Map the hero conclusion, overview table, explanation, action, sources, and limitations before styling. Choose a visual only when it answers a real question.

  3. Art-direct the subject

    Set named colors, type roles, layout sketches, and one signature move. Reject any choice that could move unchanged to an unrelated report.

  4. Critique, remove, and verify

    Check source integrity, keyboard focus, mobile layout, reduced motion, print output, and the strict validator. Remove one element that does not help the reader.
