# HTML Report — Design System

This is the canonical visual contract for reports generated by the skill. Content must come from the current task; the design system does not authorize reusing facts from prior reports.

## Visual Character

- Dark, calm, technical, and evidence-oriented.
- Deep navy page background with a subtle radial blue accent near the upper-left.
- Rounded dark panels with fine blue-gray borders and restrained shadows.
- High-contrast off-white text, muted blue-gray secondary text, and a bright blue interaction accent.
- Green, yellow, red, and blue semantic status colors; color must never be the only carrier of meaning.
- Dense information is split into cards, tables, figures, and short paragraphs rather than walls of text.

## Canonical Tokens

```css
:root {
  color-scheme: dark;
  --bg: #0b1220;
  --panel: #121c2d;
  --panel-2: #18253a;
  --text: #e8eef8;
  --muted: #a9b7cb;
  --line: #2b3b55;
  --green: #50d890;
  --yellow: #f7c65c;
  --red: #ff7373;
  --blue: #65b5ff;
  --code: #07101c;
  --radius-lg: 16px;
  --radius-md: 12px;
  --shadow: 0 14px 36px rgb(0 0 0 / 22%);
}
```

Use semantic aliases when useful (`--success`, `--warning`, `--danger`, `--info`) but keep these source tokens as the single palette definition.

## Page Shell

- Content width: `min(1120px, calc(100% - 32px))`.
- Desktop outer margin: about `36px auto 64px`.
- Header and major sections: `16px` radius, `1px` border, subtle shadow.
- Major section padding: `24px`; hero padding: `30px`.
- Mobile breakpoint near `620px`; reduce outer width and panel padding without horizontal scrolling.
- Use one `<main>` landmark and a logical heading hierarchy.

## Typography

- Stack: `system-ui, -apple-system, "Segoe UI", sans-serif`.
- Body: `16px/1.6` or equivalent.
- Hero title: responsive `clamp(1.9rem, 5vw, 3rem)`.
- Section title: about `1.45rem` with a lower border.
- Avoid all-caps except compact labels/badges.
- Code/log output: system monospace, wrapped or horizontally scrollable as appropriate.

## Components

### Hero

Include:

- a compact type/status badge;
- one descriptive `<h1>`;
- a lead stating scope and provenance;
- a conclusion callout;
- confidence/limitations when appropriate.

### Overview table

Every report includes one table marked `data-overview`. It should map the document at a glance using columns appropriate to the task, such as:

- Area / finding / impact / next action;
- Stage / objective / owner / completion signal;
- Option / fit / trade-off / recommendation;
- Section / question answered / evidence.

The table is not a table of contents unless a table of contents is the most useful overview.

### Cards and findings

Use `.grid` with responsive `minmax()` columns. Cards may represent metrics, findings, options, risks, or milestones. Each status card includes a textual label as well as a color.

### Callouts and badges

- Success: green.
- Warning: yellow.
- Failure/blocker: red.
- Context/information: blue.

Use a badge for category/severity and a callout for a conclusion or important constraint. Do not decorate every paragraph.

### Steps

Numbered step cards should include:

- action-oriented heading;
- rationale;
- concrete commands or artifacts when relevant;
- expected result/verification;
- approval boundary for disruptive actions.

### Evidence and sources

Use tables, `<details>`, code blocks, and source lists. Keep raw logs bounded; summarize repetitive messages and preserve decisive excerpts.

### Figures

Wrap each graph, diagram, or illustration in `<figure>`, provide `<figcaption>`, and mark machine-checkable purpose with:

```html
<figure data-visual-kind="graph|diagram|illustration" data-purpose="Short explanatory purpose">
```

Inline SVG should use `role="img"` with `aria-labelledby` pointing to a `<title>` and `<desc>`.

## Tabs

Tabs are progressive enhancement for long reports, not a default decoration.

- Use `role="tablist"`, `<button role="tab">`, and `[role="tabpanel"]`.
- Preserve normal document reading order in source.
- Default to summary/overview.
- Support ArrowLeft/ArrowRight, Home/End, click, and URL hash.
- JavaScript adds the `tabs-ready` class and then hides inactive panels. Without JavaScript, all panels remain visible.
- Print CSS hides tab controls and reveals all panels.

## Motion

Keep animation subtle and optional. Honor:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { scroll-behavior: auto !important; transition: none !important; }
}
```

## Print

- Switch to a light, ink-efficient surface.
- Reveal all tab panels and expanded explanatory content needed for comprehension.
- Avoid clipped code, figures, and tables.
- Use `break-inside: avoid` for cards and figures where practical.
- Preserve semantic status with labels/borders if colors are unavailable.

## Prohibited Patterns

- External font/CDN dependencies by default.
- Neon/glowing dashboard aesthetics.
- Decorative charts without real data.
- Color-only severity indicators.
- Tiny text used to force content into cards.
- Fixed-height panels that clip content.
- Tabs on short pages where normal scrolling is clearer.
