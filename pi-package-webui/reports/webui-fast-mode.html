What “speedup” means here: it is not a wall-clock, network, DOM-CPU, model token/s, or inference claim. It is a deterministic reduction in the explicitly counted post-parse serialized JSON work for one fixed trace and one connected browser. The shared inbound parse term is intentionally retained in both modes.

Scope boundary

The optimization starts after Pi RPC JSON parsing. It does not alter Pi input serialization, prompts, provider/model behavior, tools, inference, extension execution, transcript APIs, or dependencies.

Final authority

Compact live output is temporary plain text and lightweight tool status. Existing /api/messages reconciliation remains the authority that restores rich Markdown, thinking formatting, and complete tool cards.

Operational posture

Normal is the default. A compact and a normal client may observe the same tab independently, and server-default changes affect auto-negotiated clients only. The primary UI path is sidebar Controls → Output processing; Browser workflow settings expose the same persisted server default.

Approved contract and output flow

The feature establishes a small, versioned browser contract rather than persisting a client choice in a tab or Pi process. The server owns the default; each EventSource connection chooses a representation safely.

Configuration

Server default

Accepted modes are normal and compact-v1. Resolution is explicit --output-mode → PI_WEBUI_OUTPUT_MODE → persisted outputModeDefault → normal.

Settings schema is v4. Missing or invalid persisted values normalize to normal; invalid CLI/environment values stop startup with an actionable error.

API

Authenticated configuration

GET /api/webui-output-mode and PUT /api/webui-output-mode expose or persist persistedDefault, effectiveDefault, source, and overridden.

PUT is remote-auth-gated, writes even while CLI/environment overrides, and does not restart Pi or mutate session state.

Controls + settings

Output processing selectors

The sidebar Controls → Output processing group is the primary control: choose Normal or Fast, then Apply. It displays persisted default, effective mode, source, and a CLI/environment override when one wins. A transient failed save stays visible but remains retryable.

/settings → Browser workflow exposes the same persisted value. Both send only { outputModeDefault } to the separate output-mode PUT endpoint and refresh metadata; neither enters the Pi SettingsManager payload.

SSE v1

Connection negotiation

Browsers use /api/events?tab=<id>&outputMode=auto&outputModeProtocol=1. Invalid/missing/old negotiation receives normal protocol 0; compact activates only after a protocol-1 acknowledgement.

A new browser talking to an old server retries once with explicit normal mode and does not loop.

Semantic barrier ordering

For an active auto client, the server forwards the barrier in the old representation, emits an untransformed webui_output_mode control with protocol version 1, then switches the descriptor for later events. Barriers are message_end, tool_execution_end, agent_end, agent_settled, compaction_end, pi_process_exit, and pi_process_error. This avoids a single semantic unit receiving two representations.

Deterministic methodology and acceptance

The primary fixture has exactly 512 ordered 32-byte ASCII assistant deltas and 16,384 final assistant bytes. Each delta event carries cumulative top-level and nested snapshots in normal form. Lifecycle, tool start/end, and diagnostic records surround the trace and remain part of semantic parity. Fresh deterministic fixtures are encoded through the production seam for each mode.

Formula: Wmode = R + 2 × Smode. R is the UTF-8 byte sum of JSON.stringify for parsed inbound RPC events. S is the UTF-8 byte sum of production-encoded browser JSON. The multiplier counts the browser-bound JSON serialization and browser JSON parse visits. SSE framing bytes are deliberately excluded.

Examples

Start compact by CLI

pi-webui --output-mode compact-v1

CLI is the highest-priority server default. Existing explicit normal clients remain normal; auto clients negotiate the effective default.

Set an environment default

PI_WEBUI_OUTPUT_MODE=compact-v1 pi-webui

Environment applies when the CLI flag is absent. Invalid environment values fail startup instead of silently selecting a mode.

Enable from Controls

Controls → Output processing
Fast → Apply

The sidebar selector writes the persisted setting through the separate authenticated endpoint and refreshes its metadata. The equivalent API body is { "outputModeDefault": "compact-v1" }; CLI/environment can still temporarily override the effective result.

  1. Roll out from the normal default

    Use sidebar Controls → Output processing → Fast → Apply. Equivalent paths are --output-mode, PI_WEBUI_OUTPUT_MODE, /settings → Browser workflow, or the API. The controls display the persisted value separately from an effective CLI/environment override. Observe diagnostics and reconciliation; do not market elapsed-time improvement from this evidence.

  2. Roll back operationally first

    Choose Normal under sidebar Controls and Apply, use /settings → Browser workflow, send { "outputModeDefault": "normal" } to the configuration API, or remove the CLI/environment compact override. Idle auto clients switch immediately and active auto clients switch at the next semantic barrier. Explicit compact clients remain explicit until reconnecting or requesting normal.

  3. Revert code only as a coordinated unit

    If code rollback is required, revert the transport and browser work together or force the server default to normal first. No session, transcript, prompt, tool, model, provider, or data migration exists to undo.

Remaining risks and limitations: no interactive visual-browser run exercised actual paint/reconciliation timing or the settings dialog, so no screenshot is included; compatibility with a historical released server was structural rather than binary-to-binary; and compact live tool bodies are intentionally deferred until final reconciliation. The settings control's placement, API wiring, metadata, payload exclusion, and unavailable-API fallback are structurally covered. These limits do not alter the deterministic parity or full-suite result, but they bound the confidence claim.

Integration schema-test fix

The settings migration changed the normalized schema to v4. The remote-auth harness expectation was intentionally aligned from schema 3 to schema 4, then included in the all-46-file package check. This is an integration compatibility test correction, not a configuration policy change.

Evidence interpretation

Production transform and browser scheduling have separate ledgers. Their common requirement is semantic final-output preservation. Neither ledger claims measured end-user latency, model throughput, or a universal performance result beyond the fixed, stated workload.

Hygiene

The completion-fix run changed only public/app.js, tests/fast-mode-client-static.test.mjs, and its handoff. This final reporting correction changes only the canonical plan and report. No dependency, lockfile, generated file, or commit is created by either reporting step.

Why the semantic hash matters

Byte reduction alone would not establish a safe output-mode change. The metric reparses every emitted normal and compact browser payload and reduces ordered text, content indices, lifecycle records, tool start/end data, errors, and final message semantics. It requires deep equality and equality of the stable SHA-256 payload before accepting the ratio. The hash is therefore a compact witness for the independently compared canonical semantic payload, not a replacement for the test assertions.

Why normal remains the default

Compact mode deliberately trades rich progressive formatting and intermediate tool-body construction for bounded live display work. The browser restores full rich output from final messages, but normal remains the compatibility-preserving default for every connection that does not explicitly negotiate protocol 1 and an applicable compact selection.
