Design and interaction flow

State boundary

workflowOverlayMinimizedByTab is independent from the existing inspector and subprocess Minimize controls. Closing the complete overlay changes only presentation state for the active terminal tab.

Single source of restore truth

The Open helper appears only when Workflow content exists and that tab is minimized. Live payload updates still rerender the composer control while the overlay remains closed.

Implementation map

public/index.html

Groups the existing Workflow Mode button with a circular, initially hidden Open helper. The helper labels its purpose and controls the widget area.

public/app.js

Adds per-tab minimize state, content detection, composer-control rendering, close/open transitions, focus recovery, tab cleanup, and a render gate covering both specialized Workflow widgets.

public/styles.css

Matches the app-runner helper pattern, styles the Close action, reserves an anchor box when the mode button is unavailable, and keeps the Close action touch-friendly on compact layouts.

tests/mobile-static.test.mjs

Locks markup grouping, tooltip behavior, state isolation, teardown, renderer gating, event wiring, focus recovery, and CSS anchor/visual contracts.

Non-destructive by construction. Neither Close nor Open sends a slash command or backend request. Workflow execution, replayed payloads, and Workflow Mode remain unchanged.

Independent review dispositions

Accepted
Anchor-box collapse. The Google reviewer showed that an absolutely positioned helper could lose its layout anchor if the mode button were hidden. .has-open-control now reserves a 1.95rem box, with a focused assertion.
Accepted
Duplicate tooltip. The Open helper's native title was removed so it uses the styled tooltip plus accessible label without double browser tooltips.
Rejected
Clear minimize state after completion. Persistence is the requested minimize behavior. Completion does not remove replayed content, and clearing state on transient content loss could unexpectedly reopen the overlay.
Rejected
44px badge as an AA requirement. The compact badge intentionally matches the app-runner helper pattern and exceeds WCAG 2.2 AA's 24px target minimum; 44px is enhanced guidance rather than the claimed AA blocker.
Deferred
Behavioral DOM harness and dedicated wrapper. Both would improve future confidence or ARIA precision, but the repository's neighboring controls use focused static contracts and the direct call graph was independently reviewed without a functional blocker.

Reviewer confidence: Anthropic 88/100; Google 92/100. No accepted blocker remains.

Usage and rollback

  1. Run or inspect a Workflow until the Workflow inspector or subprocess overlay is visible.
  2. Select Close in the first Workflow card header. Both Workflow surfaces disappear, but execution and payload state continue.
  3. Select the circular Open workflow overlay helper on the composer Workflow control to restore the complete view.

Rollout requires only a WebUI reload. Rollback is a direct revert of the localized markup, browser renderer, CSS, test, plan, and report changes; no migration or cleanup step exists.

Residual risks and evidence boundaries

  • No browser automation harness currently clicks the live controls; validation combines source contracts, direct control-flow inspection, syntax checks, and two independent reviews.
  • The complete Workflow overlay consists of two sibling widgets, so both controls reference the containing widgetArea instead of a dedicated wrapper.
  • The full package suite is not green because of an unrelated dependency-version fixture mismatch in pre-existing package metadata changes.
  • package.json and package-lock.json were already modified and are excluded from this feature's scope.
