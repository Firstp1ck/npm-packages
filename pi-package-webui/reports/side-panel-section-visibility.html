Design decisions and architecture

Lightweight classification

One cohesive UI slice

The change stays within the existing static Web UI shell: markup, client state/event handling, styling, and one focused test. It introduces no server contract, migration, dependency, or deployment change, so a canonical complex-feature plan was not required.

Single source

Discover sections from the DOM

sidePanelSectionRecords() already defines the valid section set. The menu maps those records at open time, so adding a future section automatically adds it to the menu without a second list.

Independent state

Visibility does not replace collapse

Hidden section IDs use pi-webui-side-panel-sections-hidden. The pre-existing expanded/collapsed preference remains intact, so re-showing a section restores its accordion state.

Menu coexistence

Preserve specialized actions

File and Git row context menus stop propagation and mutually close the section menu. Native link and text-entry context menus remain available.

Usage, rollout, and residual risks

  1. Open the side panel. Right-click a non-editable area. Keyboard users can focus a side-panel control and press the Context Menu key or Shift+F10.
  2. Choose visible sections. Checked entries are shown; selecting an entry toggles it immediately. The menu remains open for multiple changes.
  3. Continue normally. Click elsewhere or press Escape to close the menu. Visibility persists in this browser and synchronizes to other tabs through the storage event.
Rollout

No migration

The new storage key defaults to an empty hidden list. Existing users therefore keep all sections visible until they choose otherwise.

Residual risk

Browser behavior not visually exercised

Viewport clamping, native context-menu preservation, and focus movement are source-verified and review-verified, but not observed in a headless or manual browser session during this run.

Rollback

Self-contained removal

Rollback consists of removing the context-menu markup/style/handlers and the visibility storage functions. Existing stored hidden IDs become inert and do not affect older code.
