Design and implementation

Pi's documented session format represents extension-injected messages as role: "custom", with either a string or structured text/image content array. The WebUI already rendered assistant content as Markdown through renderContent. The change extends only that opt-in condition:

renderContent(body, message.content, {
  markdown: message.role === "assistant" || message.role === "custom"
});

String content

Flows to appendMarkdown after transcript-progress stripping.

Structured content

Every type: "text" part uses the same Markdown path; image parts retain existing image rendering.

Unknown roles

Continue to default to plain text, preserving the existing fail-safe behavior.

Usage, rollout, and rollback

No user configuration or migration is required. Extension messages already returned by Pi as role: "custom" will display headings, lists, links, code blocks, tables, and other supported Markdown in the WebUI.

Rollback is a one-line condition removal plus deletion of the focused test. No persisted data changes are involved.
