Requested behavior

The previous single-node text-overflow: ellipsis behavior kept the start and dropped the tail. For paths, the tail often contains the repository or project name, so losing it removes the most useful discriminator.

Architecture and data flow

Implementation map

public/app.js

splitMiddleTruncationText creates code-point-safe start/end parts. setMiddleTruncatedText builds safe text spans without innerHTML.

Enhanced footer integration

renderGitFooterPayloadMeta opts in only when chip.key === "cwd". updateGitFooterChipNodeValue retains the structured value during live updates.

Fallback footer integration

renderTuiFooterLine passes the same option to the CWD item in both tab-present and loading branches.

public/styles.css

The container is a bounded flex row. The start has a six-character floor and owns the ellipsis; the complete final component is non-shrinking, with 16 characters retained when that reaches farther back.

tests/footer-middle-truncation.test.mjs

Tests boundaries, POSIX and Windows final components, trailing separators, reconstruction, disabled splitting, Unicode surrogate safety, both render paths, dynamic updates, and CSS structure.

Deferred · impossible-width cases

A final component wider than the whole container cannot coexist with a visible prefix. Both reviewers classified this as the acknowledged physical layout limit; mobile grants CWD a full row and the tooltip keeps the full path.

Accepted · preserve beyond 16 characters

When the final component is longer than 16 characters, the suffix now starts at its nearest / or \. When shorter, the original 16-character minimum may intentionally reach into the preceding component.

Residual risks and usage guidance

Residual: extreme widths

If a footer value becomes narrower than the six-character prefix floor plus the complete final component, overflow is unavoidable. Existing mobile layout gives CWD the full row, reducing this risk.

Residual: pixel rendering

The implementation uses standard flex and overflow semantics, but exact font and viewport rendering was not exercised in a real browser during this change.
