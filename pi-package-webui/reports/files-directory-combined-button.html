Lightweight feature · verified

Files directory rows now use one expansion button

This report covers the scoped Pi WebUI change that places each directory arrow and directory label inside one accessible Files-sidepanel button. It is grounded in the current source diff, focused checks, and two provider-diverse independent reviews.

Conclusion: clicking the arrow, directory icon, or directory label now invokes the same row button and toggles that directory. File opening, search reveal, overflow actions, context menus, drag-and-drop, and tree keyboard semantics remain wired.

Classification: lightweight. The evidence shows one bounded client-side rendering/interaction slice with matching CSS and static-test updates; there is no new API contract, migration, security boundary, dependency, or rollout mechanism. A canonical complex-feature plan was therefore not required.

Confidence: 94/100. Source structure, syntax, focused assertions, Git diff hygiene, and two independent reviews agree. Confidence is below 100 because no browser-level click simulation was run and the package-wide static test stops on an unrelated baseline typography rule.

Design and interaction flow

Single target

One accessible action

The row button owns role="treeitem", aria-selected, and—on directories—aria-expanded plus an Expand/Collapse accessible label. The arrow is decorative to assistive technology.

Preserved sibling

Overflow stays separate

The ellipsis action remains a sibling button with its own event handling, so combining the directory row does not nest buttons or absorb menu actions.

Existing state path

No new state model

The change reuses fileTreeState.expanded, toggleFileTreeDirectory(), and revealFileTreeEntry(). Only the click target and DOM composition changed.

Usage, rollout, and residual risk

Use

Open the sidepanel's Files section, then click a directory's arrow, icon, or name. The directory should expand; clicking the same row again should collapse it. The ellipsis remains a separate actions button.

Rollout

No migration, storage reset, server restart contract, or API change is required. The updated client assets take effect through the package's normal WebUI asset delivery and cache/version workflow.

Residual risk

Low. The main unverified dimension is browser-rendered behavior under pointer and keyboard input. The preserved existing functions and two reviews reduce—but do not eliminate—that risk.
