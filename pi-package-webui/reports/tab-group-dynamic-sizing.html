Dynamic tab-group sizing

Terminal tab-group menus now expand to the natural height of their open tabs instead of imposing a capped, internally scrollable viewport.

Conclusion: The scoped CSS change meets the no-internal-scroll requirement across default desktop, dense, left-sidebar, and mobile layouts. All 41 package test files passed, and two provider-diverse independent reviewers found no blockers.

Design decision and architecture

Beforemax-height: min(60vh, 24rem)
overflow: auto

Large groups were constrained to a local scroll viewport.

Aftermax-height: none
overflow: visible

The menu grows with the number of tabs and shows the full list.

Why CSS only

The existing menu already uses a column flex layout, natural-height children, visible group overflow, open-state ancestor overflow, and a static mobile expansion. No JavaScript sizing or state change was needed.

The feature was validated as lightweight: it changes one presentation rule and its regression contracts, without affecting persisted tab groups, drag-and-drop behavior, APIs, dependencies, security boundaries, migrations, or rollout.

Finding dispositions

  • Accepted and fixed: narrowed the CSS assertion so it cannot cross rule boundaries, and explicitly guarded the ancestor overflow: visible behavior.
  • Accepted as residual risk: very large desktop groups may extend beyond the viewport; adding a cap and scrollbar would conflict with the approved requirement.
  • Deferred: a pre-existing left-sidebar hover interaction can suspend outer sidebar scrolling; it was not introduced by this change.

Usage, rollout, and rollback

No user action, configuration migration, or service rollout is required. Open a group normally; every grouped tab should be visible in the expanded menu without scrolling inside that menu.

Rollback is CSS-only: restore the previous menu height cap, overflow: auto, and thin-scrollbar rule, then update the static contract. No data rollback is needed.

Confidence: 94/100. The implementation and cascade are directly inspected, all tests pass, and both independent reviewers agreed. Confidence is below 100 because no live browser rendering was performed.
