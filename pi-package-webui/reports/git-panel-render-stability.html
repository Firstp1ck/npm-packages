Implementation map

renderGitPanelFolder()

Defines defaultOpen = depth === 0, restores a stored override when present, deletes a key when the toggle equals the default, and stores only a deviation.

renderGitPanel()

Prunes stale root state, computes rendered inputs, skips a same-signature rebuild when top-level card count is intact, and no longer hashes the always-true sectionExpanded.

Sibling guards

renderContextMeter() and renderWorkspaceDashboard() compare their own visible-state inputs before replacing children.

Residual risks and limitations

Live-root override retention

Overrides for vanished paths can remain while a root stays live. Canonicalization limits growth to folders the user actually toggled.

Signature maintenance drift

A future rendered value must also be added to its co-located signature or DOM could remain stale until another input changes.

Browser behavior unexecuted

Timing, focus, and scroll behavior were reasoned from source and covered structurally, not executed in a browser/jsdom harness.

Repository-wide check blocked

The unrelated optional-companion package-lock mismatch prevents a full green npm run check.

Usage and verification guidance

Exercise unchanged polling

Expand Git, close a top-level folder, open a nested folder, and observe several active-agent poll cycles. Unchanged inputs should preserve DOM and choices.

Trigger a legitimate update

Change the Git snapshot or switch Changes/History. The signature should change, the panel should rebuild, and stored folder deviations should be restored.

Check default restoration

Toggle each folder back to its depth default. A later rebuild should use top-level-open/deeper-closed without retaining an explicit map entry.
