Architecture and event flow

Resource model

A canonical root owns one watcher and a set of tab IDs. The final unsubscribe closes its timer and watcher. Shutdown closes all roots.

Authority model

Filesystem events never attempt to classify Git state. They only invalidate; /api/git-panel runs bounded Git reads and returns the authoritative snapshot.

Feedback prevention

Read-only status/diff commands receive GIT_OPTIONAL_LOCKS=0, preventing optional index refresh writes from feeding back into the watcher.

Failure model

Watcher errors are diagnostic and non-fatal. Git read errors stop automatic render retries until a new invalidation or explicit refresh.

Race handling

if an SSE invalidation arrives while /api/git-panel is loading:
  mark refreshPending = true
  let the current request settle
  render its result or error once
  queue exactly one forced follow-up read

Finding dispositions

Accepted and fixed — unbounded read-error retries. Error snapshots are skipped by visible-refresh reconciliation; a new invalidation clears the error and retries once.
Accepted and fixed — sustained-write starvation. A 2 s maximum wait now bounds the trailing debounce.
Accepted and fixed — tab-start cleanup gap. The create-tab failure path defensively unsubscribes before deleting the tab.
Deferred — watcher platform limits and build churn. Recursive watches can fail on network filesystems or host watch limits, and busy build trees can still cause periodic refresh work. Non-fatal fallback, debounce, max-wait, and in-flight bounds are the proportionate current controls.
Rejected as a new privacy defect — repository-root disclosure. The same authorized browser already receives the root/cwd; invalidations add no filenames or contents.

Residual risks

  • Watcher events are not replayed after an SSE disconnect; cache expiry or manual refresh recovers missed changes.
  • Browser DOM timing and pending-refresh behavior are reviewed and structurally tested, not run in a browser automation harness.
  • Recursive watcher reliability depends on the host filesystem and watch limits.
  • No workload benchmark was run for very large repositories or sustained generated-file churn.
Rollout guidance: open the Git section, expand a repository, then create/edit/rename/delete a file. The Changes count and tree should refresh after the debounce window. Collapse the section, change a file, and re-open it to confirm deferred refresh. Manual Refresh remains the fallback.
