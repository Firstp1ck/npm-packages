Workflow Overlay Navigation

A lightweight WebUI refinement that gives workflow status, phase, task progress, and output limits a clear hierarchy while making live terminal scrolling predictable instead of forcing the reader back to the newest line.

Conclusion: the workflow overlay now separates summary information from actions and output, preserves the reader’s terminal position per tab and run, and keeps horizontal log scrolling local. Syntax, focused tests, the full 41-file package suite, and a cross-provider review quorum passed.

Scope: public/app.js, public/styles.css, tests/mobile-static.test.mjs. Confidence: 96/100. A browser pixel comparison was not available; runtime layout confidence is based on source inspection, CSS cascade analysis, focused contracts, and three successful independent reviews.

Interaction and layout design

Summary

Readable at a glance

Compact labeled cards replace a row of visually equal pills. Status colors remain semantic, but labels carry the meaning without relying on color alone.

Reader control

Auto-follow is conditional

A 24-pixel near-bottom threshold decides whether new output follows the live tail. The footer says when following is active or paused.

Responsive

Three layout states

Desktop uses a three-part header; at 1100px metadata moves to its own row; at 720px it becomes a two-column grid and help text stacks.

Accessibility

Limits are visible

The summary uses role="group" with an accessible label. Output-limit detail is visible text rather than a hover-only native tooltip.

Residual risks, rollout, and rollback

Residual

No browser pixel test

Static CSS and source contracts cannot fully prove visual density on every browser/zoom combination. A manual check against a long live workflow remains useful.

Low impact

Closed-tab state

The in-memory map can retain one small record for a formerly rendered tab until page reload. It contains only booleans and pixel position, not output content.

Rollout

No migration

The change is browser-only and activates with the existing workflow widget payload. Reloading the WebUI is sufficient.

Rollback

Localized revert

Revert the scoped renderer, CSS, and test hunks. No stored data, protocol, package dependency, or server route needs rollback.

Recommended manual acceptance: open a long-running workflow, scroll upward, confirm the footer changes to “Auto-follow paused,” let new lines arrive without a jump, then scroll to the bottom and confirm follow resumes. Check that long log lines scroll horizontally only inside the terminal.
