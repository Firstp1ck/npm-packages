Architecture and data flow

RPC correlation

Reply listeners are installed before requests are emitted. A bounded completion cache covers a child finishing before the spawn reply reaches the gate.

Quorum semantics

Only successful, non-excluded, provider-eligible outputs count. Queued slots stop launching once quorum is met; already-running attempts finish normally.

Lifecycle retention

The helper retains at most 32 gate snapshots, each with at most 100 attempts. Every boundary truncates untrusted strings before browser rendering.

Cancellation reconciliation

A spawn reply is preserved after abort long enough to recover a late run ID. The attempt becomes terminal and the gate sends a bounded RPC stop.

    The existing WebUI package extension now registers subagent_gate, and settings changes are read when a new/reloaded session starts.

  2. Use ordinary delegation by default

    Continue using subagent for calls that do not need retry or quorum semantics. Use subagent_gate only when those guarantees matter.

  3. Declare safety conservatively

    Omit retrySafety or use may-write unless rerunning the child is demonstrably idempotent and read-only.

  4. Inspect retained attempts

    The Subagents side panel shows quorum, provider/model, failure class, retry lineage, and terminal state after children disappear from the running list.

Residual risks
  • No live-provider end-to-end test exercised the real RPC bridge; installed pi-subagents source and the exact v1 event/reply contract were inspected instead.
  • Fallback availability still depends on provider credentials, quotas, and account health. The gate exposes exhaustion rather than claiming unavailable outputs.
  • Agent-level fallbackModels are an intentionally limited stopgap. They can retry internally before the outer gate sees a completed attempt.
  • Terminal histories are session-local and bounded, not a durable audit database.
  • The WebUI and dotfiles worktrees were already dirty. Edits were narrow; no unrelated changes were reverted or reformatted.
Fallback configuration

The exact order is anthropic/claude-opus-4-8 → openrouter/moonshotai/kimi-k3 → openai-codex/gpt-5.6-sol. It is applied only to reviewer, scout, planner, context-builder, researcher, and oracle. Mutation-capable workers were intentionally excluded.
