Image Payload Error Hardening

Source-grounded report for the Pi WebUI fix that exposes malformed tool images and terminal Codex errors while rejecting non-canonical browser image payloads before RPC dispatch.

Conclusion: the silent-failure path is closed within the approved WebUI scope. Invalid browser payloads now fail with HTTP 400 before reaching Pi, malformed tool images produce an actionable transcript warning, and terminal assistant errors have an agent_end fallback. Two independent cross-provider reviewers approved the implementation.

Confidence: high for server/RPC behavior and event-handler structure. Real-browser transcript timing was not automated, and existing malformed session history is intentionally not rewritten.

Diagnosis and failure flow

The decisive evidence was structural rather than speculative: affected session tool results stored image strings beginning with 137,80,78,71,13,10,26,10, the decimal PNG signature. Those strings failed alphabet checks and canonical round-tripping. The repository's workbook renderer had already been corrected, but the observed installed @firstpick/pi-extension-workbook@0.1.1 still used Uint8Array.toString("base64"), which produces comma-separated decimal values rather than encoding bytes.

Why not silently drop the image? Altering or hiding a tool result would mutate model context semantics and could conceal a producer defect. The implementation fails closed for browser input, warns for runtime tool output, and preserves existing session integrity.

Implementation details

Server boundary

decodeCanonicalBase64

Normalizes an optional data-URL envelope and whitespace, requires non-empty standard base64 with length divisible by four, decodes it, and requires the decoded bytes to re-encode to the exact same string.

This rejects comma-separated bytes, URL-safe alphabets, invalid pad bits, malformed padding, and unpadded values that permissive decoders might accept.

Transcript visibility

toolImagePayloadError

Checks tool-result image blocks at tool_execution_end. An invalid block produces a visible, actionable warning without copying potentially huge or sensitive image data into the transcript.

Terminal fallback

assistantErrorFromAgentEnd

Reads only the last assistant message in the low-level run. It surfaces a terminal stopReason: "error" only when no normal final-message diagnostic was already shown and no retry is pending.

Preservation

Valid input remains unchanged

Decoded byte length replaces a padded-string approximation for limits. Valid raw base64 and normalized MIME values continue into the Pi RPC command without recompression or content transformation.

Why the broad checks are not marked fully green

The two WebUI failures occurred after the focused image hardening test had passed: a Windows file lock prevented deleting a temporary merge-conflict fixture, and the current account could not create a symbolic link. Repeating the broad HTTP harness reproduced the same unrelated lock. The workbook package's TypeScript check failed while resolving a sibling development dependency. These failures are preserved rather than relabeled as feature failures or silently ignored.

Rollout, recovery, and residual risk

  1. Publish and install the corrected workbook producer

    The repository source is correct, but an installed 0.1.1 copy produced the observed malformed image. Package publication/installation is an external side effect and was not performed in this task.

    Done when: an installed render returns canonical base64 and its decoded first eight bytes are the PNG signature.

  2. Recover affected sessions without rewriting history

    After upgrading the tool, fork before the malformed workbook_render result or start a fresh session. Retrying in the same branch still sends the bad historical tool result to Codex.

    Done when: the malformed tool result is absent from active model context and a new prompt succeeds.

  3. Run focused verification after packaging

    cd pi-package-webui
node tests/runtime-error-visibility.test.mjs
node tests/image-payload-hardening-harness.test.mjs

cd ../pi-extension-workbook
npm test

    Done when: the WebUI focused tests and workbook canonical serialization test pass in the packaged environment.

Residual risk: WebUI diagnostics cannot stop Pi core from immediately making the next provider call after a malformed tool result, nor can they repair old context. The practical prevention layers are the corrected producer and strict browser-input gate; runtime warnings and terminal fallback make remaining failures visible and actionable.
