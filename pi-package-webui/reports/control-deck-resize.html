Design and behavior

Mouse and touch pointer

The separator sits on the Control Deck's left edge. Moving it left increases width; moving it right decreases width. Pointer capture and window-level move/up/cancel listeners preserve cleanup when the pointer leaves the handle.

Keyboard

When the separator is focused, Left/Right resize by 24 px, Shift modifies the step to 80 px, Home selects the minimum, and End selects the current viewport-aware maximum.

Dynamic content

The desktop grid column uses the CSS custom property while .side-panel remains width: 100% with min-width: 0. Existing controls, lists, and responsive rows therefore reflow within the selected track rather than retaining a fixed 24 rem width.

Mobile and narrow screens

At the established overlay breakpoint, the Control Deck remains a fixed inset drawer. Both resize handles are hidden, and JavaScript refuses pointer or keyboard resize starts.

Usage: On desktop, drag the colored grip on the Control Deck's left edge. The width is saved automatically in this browser. Keyboard users can focus the grip with Tab and use Left, Right, Home, End, and Shift-modified arrows.

Residual risks

  • No real-browser drag, keyboard, computed-layout, or breakpoint paint test was run; current evidence is static plus call-graph reasoning.
  • Viewport constraint changes may reduce the applied width for the current page session rather than restoring a previously larger preference immediately, matching existing file-viewer behavior.
  • The repository was already dirty with unrelated feature work. This implementation avoided reverting or rewriting those changes.
