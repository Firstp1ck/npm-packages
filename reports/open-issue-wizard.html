Open Issue Wizard

Implementation, verification, and rollout record for the five-step GitHub issue wizard added to the Pi WebUI Control Deck. Evidence comes from the integrated working-tree diff, focused tests, package checks, two implementation handoffs, and two fresh provider-diverse reviews.

Conclusion: The feature meets the approved behavior and safety contract. It is ready for use as a copy-first issue composer; automated GitHub submission remains deliberately unavailable until a separately reviewed bot/backend contract exists.

Confidence: High for domain behavior, runtime asset delivery, static accessibility contracts, and no-I/O submission gating. Live browser layout/focus automation was unavailable on this machine, and the package baseline remains red for seven unrelated existing Windows/environment failures.

Scope and approved decisions

Included

  • Feature, Bug, UX, Documentation, Performance, Compatibility, and Other categories.
  • Exactly one component: WebUI or a label derived from the existing optional-feature catalog.
  • Compatible template names with descriptions and field previews.
  • Structured dropdown/toggle controls plus minimal required prose inputs.
  • Exact GitHub title and Markdown body preview with complete-copy action.

Intentionally excluded

  • GitHub tokens, OAuth, bot/backend endpoints, or any network submission.
  • Draft persistence, attachments, automatic log collection, and unrelated WebUI refactors.
  • A public Security category, to avoid steering sensitive disclosures into normal public issues.
  • Enabling the bot button before a separate security-reviewed contract exists.

The title format is fixed as [Category] [Component] [Template] Short summary. Changing a category or component clears dependent template/form state while retaining the independent summary.

Architecture and interaction flow

Domain ownership

issue-wizard-state.mjs owns catalog generation, compatible templates, reducer transitions, validation, normalization, title/body construction, clipboard text, and the unavailable adapter.

Browser ownership

app.js owns safe DOM rendering, one-page visibility, focus preservation, navigation, clipboard feedback, and passing existing optional-feature labels into the pure module.

Presentation ownership

index.html provides the fixed footer and labelled dialog shell; styles.css provides desktop/mobile layout, readable template previews, and review controls.

Usage and rollout guidance

  1. Open the composer

    Expand the Control Deck and select Open Issue in the fixed bottom-right footer.

  2. Choose structured context

    Select one category, one affected component, and one compatible template. Each template card previews its purpose and fields before selection.

  3. Complete the template

    Use dropdowns and toggle buttons where available, then add only the required prose. Continue becomes available only when the current page is valid.

  4. Review and copy

    Inspect the exact GitHub title and Markdown body, then choose Copy complete issue. The disabled bot button explains that automated submission is coming later.

Future bot phase

Implementing real submission requires a separate design for authentication, authorization, server-side GitHub API access, rate/error handling, sensitive-data policy, auditability, and user confirmation. The current async adapter is the narrow integration seam, but enabling the control without that review would violate the approved safety boundary.

Rollback: The feature is file-local and introduces no persistent schema or backend state. Rollback removes the footer/dialog/controller/styles/tests/module and restores runtime asset/check entries.
