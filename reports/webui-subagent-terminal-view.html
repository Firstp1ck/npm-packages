Selectable subagent terminal views in Pi WebUI

This report documents the implemented view-only subagent terminal-tab option in pi-package-webui, the design decisions behind it, verification evidence, independent cross-provider review, and remaining limitations.

Conclusion: Users can retain the existing overlay behavior or open a running child in a clearly marked virtual Subagent tab. Dedicated tabs render full-width transcript cards and the main-style pulsing Agent is running: card with current child activity and visually current elapsed time. The view remains intentionally non-interactive, and closing it performs no stop, interrupt, abort, or backend terminal-close action.

Confidence: 97/100. Syntax, focused helper and HTTP harnesses, checked-in VM refresh behavior, source-level lifecycle assertions, and a final fresh Anthropic Opus 4.8 review support the result. Confidence is reduced by the absence of automated browser geometry and assistive-technology coverage and one unrelated pre-existing package-lock test failure.

Architecture and lifecycle

The backend terminal remains selected through activeTabId. A separate activeSubagentTerminalId chooses whether the main WebUI surface presents the parent transcript or a virtual child transcript. This prevents the child view from acquiring backend tab lifecycle semantics.

Identity

Stable composite key

The virtual view key serializes the parent tab ID, run ID, and agent ID. This prevents duplicate tabs for the same child while keeping identically named children distinct.

Polling

Meaningful-update guard

Each view increments a request serial and compares snapshots with transport-only timestamps removed. Unchanged polls preserve transcript/tab DOM and update only the existing visual elapsed-time node.

Completion

Last snapshot retained

A 404 marks the view finished, disables further refresh, and keeps the most recent transcript visible rather than deleting the tab.

Review-driven corrections

The original reviewer identified one low-impact mode-switch edge case. The final implementation deactivates any virtual child surface at the start of openSubagentOverlay, before deciding whether the parent backend tab must change.

The follow-up reviewer then found one-second background polls rebuilding and re-announcing unchanged transcript content. The corrected refresh path compares meaningful snapshots, keeps routine status non-live, mutates only an existing aria-hidden elapsed node for unchanged polls, and labels retained 404-completed views as finished. A VM behavior assertion protects zero transcript/tab rerenders during unchanged polling.

Usage, behavior, and residual risks

  1. Choose the opening mode

    Open the WebUI side panel, expand Subagents, and select Overlay or Tab / terminal under “Open subagents in.” The choice is saved in this browser. Overlay is the backward-compatible default.

  2. Open a running child

    Click a running child row. In Tab / terminal mode, the WebUI creates or focuses one marked Subagent tab for that parent/run/child identity.

  3. Observe output

    The child surface polls the existing bounded output endpoint, renders assistant/tool cards across the full dedicated-tab width, and shows the pulsing Agent is running: card with the current tool/activity and elapsed runtime. It retains the last snapshot and finished status if the child stops being tracked.

  4. Interact through the parent

    The child input is disabled and explicitly view-only. Return to the owning parent terminal to send any message or control the run.

  5. Close without stopping work

    Use the × on the marked subagent tab. This removes only the browser view and restores the parent surface; the child run remains unaffected.

Residual risks and non-goals

Accepted

No browser interaction automation

Open/focus/close/reopen and measured geometry remain source-contract tested. Unchanged polling has checked-in VM behavior coverage, but no real assistive-technology test.

Non-goal

No child messaging

The tab intentionally provides no steer, follow-up, resume, stop, interrupt, or abort controls.

Non-goal

No reload persistence

The opening preference persists, but currently open virtual child tabs do not survive a browser reload or server restart.

Non-goal

No completed-child rediscovery

An already-open tab retains its final snapshot, but a closed completed child cannot be reopened after it leaves active-run discovery.
