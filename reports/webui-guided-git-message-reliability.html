Reliability architecture

The core change is an explicit provenance chain. The browser can display a generated pair only when the backend proves that the pair belongs to the exact request the browser is waiting for.

BackendServer-owned provenance

The UUID is generated before dispatch and stored on the originating tab with the baseline and cwd. A wrong, superseded, cross-tab, or wrong-cwd ID returns an expired readiness response.

FilesystemStable artifact identity

Identity includes size, nanosecond mtime/ctime, inode, and SHA-256. Identical text is accepted when metadata proves both files were rewritten.

FrontendSingle-flight convergence

Timer fallback, active-tab resume, and agent_end reuse the same promise for a tab/run/generation. Older polls cannot mutate newer state.

State-transition guarantees

  1. Capture before dispatch

    The backend snapshots both paths before sending the prompt. This creates a concrete baseline rather than trusting a browser timestamp.

  2. Bind before loading

    The browser stores the returned generation ID. While that response is in flight, the Refresh control is disabled and event wakeups safely no-op.

  3. Wait for complete evidence

    Both files must independently differ from baseline, contain non-whitespace text, survive a stable read, and remain unchanged across the pair settle read.

  4. Recheck ownership before render

    Immediately before state mutation, the browser verifies active workflow, tab, run ID, and generation ID again. Superseded work exits silently.

  5. Fail with recovery

    Polling is bounded. Expired records stop immediately; delayed files remain visibly pending; timeout guidance offers regenerate or verified manual preview.

Residual risks, compatibility, and rollout

Rare filesystem edge

Indistinguishable identical rewrite

On a coarse-timestamp filesystem with no useful inode change, a byte-identical rewrite may remain indistinguishable from baseline. The system fails closed after 30 seconds and asks for regeneration/manual verification; it does not show stale output.

Restart boundary

Correlation is intentionally in memory

A full WebUI server restart during generation loses the tab-owned record. This is out of scope and requires regeneration, preserving correctness over convenience.

Compatibility

Manual preview stays permissive

Preview without a generation ID preserves existing current-file behavior, including showing (empty). Correlated advancement requires non-empty files, and commit endpoints still reject empty messages.

Evidence limit

No live billed generation

Verification used unit, static, syntax, and related harness tests plus two independent reviews. A browser-driven live model generation was not run in this session.

Rollout: restart Pi Web UI so the updated backend and public/app.js load together. If versions are mixed, the flow intentionally asks for restart/regeneration instead of accepting uncorrelated files.
  • Keep dev/COMMIT/staged-commit-short.txt and staged-commit-long.txt as the canonical prompt outputs.
  • Use Regenerate after a bounded timeout; use manual preview only after personally verifying both files.
  • For future hardening, add a runtime browser/API harness that asserts promise coalescing and the backend “still settling” transition end to end.
  • Do not attribute the pre-existing working-tree edits in public/styles.css and tests/mobile-static.test.mjs to this feature.
