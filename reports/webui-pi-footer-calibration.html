Clicking PI now runs /calibrate

This report audits the Pi Web UI change that turns the extension-owned PI token metric into an always-available calibration action. It is grounded in the current implementation, focused tests, Pi extension lifecycle documentation, and two qualifying independent reviews.

Conclusion: clicking the PI metric dispatches exactly /calibrate through the active tab’s RPC path without using or changing the composer. The browser keeps a per-tab single-flight guard, exposes busy state, schedules bounded refresh attempts, and forces explicit git-footer refreshes to observe newly written calibration records.

Confidence: 94/100. Source paths, exact command construction, cache invalidation, and 21 focused/extension tests were verified. Confidence is below 100 because no live browser/provider calibration probe was run and the full package suite has unrelated working-tree/baseline failures.

Design and implementation

The value remains owned by pi-extension-git-footer-status; the browser only adds interaction to a validated PI chip. This avoids duplicating token-estimation logic in the WebUI and preserves the existing payload schema. The bare /calibrate command remains owned by pi-extension-stats, which starts its established isolated calibration session.

Disposition summary

Busy render cache — accepted and fixed

The footer fast path originally reused the old PI node, making aria-busy unreachable. The calibration in-flight bit is now part of gitFooterPickerStateKey.

Tab switch before dispatch reply — accepted and fixed

Refresh timers are scheduled before current-tab-only notification logic, while each callback still refuses UI work for a non-current tab.

60-second calibration cache — accepted and fixed

Explicit git-footer refresh now clears the cache first, so the 5s/14s/30s attempts can observe a newly recorded sample.

Refresh during streaming — risk accepted; proposed steering rejected

Using allowDuringRun: true could steer a slash command into the isolated probe turn. The safer design keeps normal idle guards and multiple bounded attempts.

Dispatch-only single-flight lifetime — deferred low risk

The requirement covers the request round trip. A narrow later duplicate window is independently blocked by WebUI streaming state and the extension’s authoritative ctx.isIdle().

Package-lock and concurrent watcher failures — rejected as feature defects

Reviewers reproduced and isolated them outside the calibration-owned diff. No unrelated concurrent writer’s files were changed or reverted.

Usage, rollout, and residual risk

Use

With the stats and git-footer companions loaded, click the PI token card. The button dispatches /calibrate; no command text is inserted into the composer.

Busy behavior

If the active tab is streaming or compacting, WebUI refuses the action and logs a warning. While dispatch is in flight, repeated clicks are suppressed.

Session behavior

Bare /calibrate starts the stats extension’s existing isolated replacement session and may use provider tokens. This is inherent to the exact command requested.

Deploy

Reload or restart Pi Web UI so the changed public/app.js is served. No payload migration or new endpoint is required.

Residual risks

  • A user who leaves the tab may not see a timer-driven update until returning; extension status publication and the next active refresh provide convergence.
  • The phrase “in the background” describes non-composer asynchronous dispatch, not preservation of the current session: /calibrate intentionally creates an isolated replacement session.
  • Static tests are intentionally source-contract tests and may require maintenance if function shapes are refactored without changing behavior.
  • The working tree contains concurrent unrelated changes. Integration must stage or commit this feature by explicit paths/hunks rather than treating every dirty file as part of the feature.
Release recommendation: ready for integration within the feature-owned paths. Preserve the documented unrelated full-suite failure separately; do not “fix” it as part of this calibration change without its own scope and evidence.
