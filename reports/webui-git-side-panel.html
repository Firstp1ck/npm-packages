Scope boundaries

Included

Local repository discovery, status tree, staging, confirmed discard/delete, recent history, commit patches, responsive styling, tests, and documentation.

Deliberately excluded

Automatic network git fetch, background polling, commit/push/pull/merge/rebase controls, recursive directory deletion, and replacement of the full Git Changes dialog.

Design and implementation

Approved decisions

  • Use terminal groups only as discovery inputs. Deduplicate repeated cwds globally before discovery, merge resolved candidates globally by canonical Git root, and render one flat card per root—never per tab, terminal, or group.
  • Keep Changes and History directly visible, with only one repository expanded globally.
  • Remove the repository toolbar and all inline folder/file action buttons; expose valid target actions through right click, Shift+F10, or the Context Menu key.
  • Keep discard/delete file-only, explicitly confirmed in the browser, and independently guarded by the server.
  • Open only top-level folders initially, show an explicit right-facing/down-facing arrow for every collapsed/expanded directory, and reserve a flexible minimum-width column for filenames.
  • Fetch local data only on first/stale expansion or explicit refresh/mutation; never add background network fetches.

Usage, rollout, and residual risk

Expected user flow

  1. Open Control Deck → Git. The WebUI takes one candidate per distinct cwd across all open tabs and resolves canonical roots.
  2. Expand a repository directly. Every canonical root appears once regardless of repeated tabs, terminals, groups, or repo subdirectory cwds. Cards use the Git-root/cwd basename; there is no session/group parent dropdown. Expanding another repository collapses the first.
  3. Use Changes. Browse folder/file disclosures; every directory has a right-facing arrow while collapsed and a down-facing arrow while expanded. File rows prioritize name width while retaining status and additions/deletions.
  4. Right-click for actions. Repository headers expose View Diff, Refresh, Stage All, and Unstage All. Folder/file rows expose only category-valid actions. Keyboard users press Shift+F10 or the Context Menu key.
  5. Use destructive controls deliberately. File-only Discard and Delete still display impact/command confirmation; the server independently validates confirmation, path scope, and file type.
  6. Use History. Select a recent commit to inspect its bounded read-only patch in the existing Git dialog.

Refresh contract

First expansion

Loads a compact local snapshot.

Fresh re-expansion

Reuses page-local data younger than five minutes.

Stale re-expansion

Reloads once the cached snapshot reaches five minutes.

Mutation/manual refresh

Forces an immediate reload and refreshes footer Git status.

No automatic remote git fetch is performed. “Refresh” means reading local repository state from the WebUI server.

Residual risks

Testing gapNo live browser automation

Expansion, one-open enforcement, focus behavior, and confirmation UX are covered by source tracing/static assertions rather than a DOM/browser harness.

Shared worktreeFull suite remains red

An unrelated concurrent manifest/lockfile edit violates the optional-companion invariant. Isolate or resolve that work separately before claiming a globally green npm run check.

Accessibility noteGeneric focusable file rows

File rows expose an accessible label and keyboard context menu but intentionally avoid an inaccurate tree/button role. Both final reviewers classified this as low/non-blocking.

Safe refusalOdd newline filenames

Untracked delete may refuse C-quoted unusual names rather than target them incorrectly. This is safe-by-refusal and optional hardening.
